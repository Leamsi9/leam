# On-demand Gmail reading

This read path is independent of Today's recent-inbox snapshot and action classifier. It uses each selected Google account's existing `gmail.readonly` grant, exact OAuth client binding and consent generation. It never requests additional scopes, sends/deletes mail, changes labels, marks read, creates Gmail drafts or modifies the Today cache. Microsoft mail is not implemented by this Gmail adapter.

`GET /api/email/mailboxes?offset=0&limit=20` lists Google account IDs, identity labels and current mail access state, with nextOffset. Select a granted connected account explicitly. Other mailboxes are reachable by repeating the same operation for their own IDs; there is no claim that one page searches every mailbox.

`POST /api/email/search` takes `{accountId, query:"", pageToken:null, limit:20, includeSpamTrash:false}`. Limit is1–20. The query is forwarded using Gmail search syntax, with no added Inbox or30-day filter. Each page performs one messages.list and at most20 metadata-only messages.get requests. Items contain exact message/thread/account IDs, bounded Subject/From/To/Cc/Date/message-reference headers, labels, receivedAt and a source link. Bodies and snippets are excluded. The result includes the same query/account, nextPageToken, resultSizeEstimate (a provider estimate, not an exact count), observedAt and untrusted-source markers. Reuse the query/account with the provider page token; pages are fresh provider reads, not a frozen search snapshot. Spam/trash remains excluded unless explicitly included.

`GET /api/email/accounts/{accountId}/messages/{messageId}?offset=0&limit=12000` reads one selected message with Gmail `format=full`. The response includes metadata, safe plaintext `text`, textFormat, offset, totalCharacters, nextOffset, contentRevision, partial, encodingLoss and attachment metadata. `limit` is1–16000 Unicode characters. To continue, pass `offset=nextOffset` and `revision=contentRevision`; missing/mismatched continuation revisions fail rather than mixing content. Each page rereads the original source under current access controls. Content revision hashes the exact account/message/text/attachment result, not a permission grant. No plaintext message cache or index is added to Leam storage. A tool result may still be retained in its selected conversation/runtime history under those existing retention rules.

MIME multipart alternatives prefer text/plain; HTML-only bodies are converted to text. Scripts, styles and hidden document metadata are excluded; links/images are never fetched, raw HTML is never returned as renderable content. Declared charsets are decoded; invalid/unknown encodings fall back with encodingLoss rather than a claim of exact decoding. Nontext and named attachments expose metadata only. Gmail may store a textual message body behind attachmentId; only those unnamed plain/HTML body parts are fetched through the same read-only authorized adapter. File attachment content is not downloaded.

Each operation checks the canonical account/provider, exact OAuth client ID, read-only scope, connected mail state and grantId before admission, before each provider request, after each await and before returning. A disconnect, client rotation or new consent discards the in-flight result. Unknown and malformed message IDs fail before provider dispatch; mismatched returned IDs fail closed. Provider details and credentials never appear in errors. Source labels/body text are untrusted reference data, never authorization to act.

Bounds:25-second operation deadline;20-second individual request timeout;8MiB decompressed response cap enforced while streaming;4MiB decoded aggregate text;200 MIME parts/depth20; at most10 external textual body fetches. Oversized, malformed, timed-out and incomplete reads fail visibly; they never return a success claiming the whole message was read. Large supported plaintext is paginated instead of silently cut off. Headers/attachment names expose truncation markers where bounded. No arbitrary URLs, filesystem paths or caller-specified HTTP methods reach the provider adapter.

`leam_email(action, accountId?, query?, pageToken?, limit?, includeSpamTrash?, messageId?, offset?, textLimit?, revision?)` shares these operations from any Companion/Today/Goals conversation. Actions are accounts/search/read; textLimit is the HTTP read limit. This new capability requires root activation as `mcp-leam.leam_email` and refreshed MCP schema discovery; installing product code alone does not prove the live model can call it. Existing tools and approval settings are unchanged.

Primary provider contracts checked2026-09-21: [messages.list](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/list), [messages.get](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/get), [message MIME parts](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages), [attachments.get](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages.attachments/get).
